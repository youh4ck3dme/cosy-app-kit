# Phase 04.5 — Builder Kernel

## Goal

Ship a headless, framework-agnostic Builder Kernel that owns the canonical design document, serializable commands, history, node registry, event bus, plugin facade, and Universal Design IR → command compiler.

## Stack policy

- Reuse TanStack Start / existing `src/lib` conventions.
- Prefer Bun (`packageManager` in `package.json`).
- Reuse existing `zod`. Do not add Zustand/Immer unless an evidenced blocker appears; the kernel is a pure TypeScript engine.
- No React types in core registry definitions.
- Keep UI selection state outside the kernel document/history.

## Required work

- Document model with decoupled layout/style/interactions/assets.
- Command system: add / remove / move / update / batch with serialize + undo.
- `HistoryEntry` abstraction and undo/redo stacks.
- Kernel event bus.
- Node registry with renderer capability flags and string renderer/generator ids.
- Plugin registry lifecycle.
- Versioned Universal Design IR + `IRToCommandCompiler`.
- Canvas RPC / sandbox contract types only (no editor UI in this phase).

## Acceptance

- Programmatically create a document, mutate via commands, undo/redo, compile IR into nodes.
- Unit tests cover validator, commands, event bus, plugins, and IR compiler.
- Typecheck and builder lint gate pass.
- No Visual Import adapters, canvas UI, marketplace, or publish wiring in this phase.

## Out of scope

- Vision/Figma/HTML adapters
- Interactive canvas / inspector UI
- Persistence to Supabase / IndexedDB
- CRDT multiplayer
